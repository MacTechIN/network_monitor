## 1. 한 줄 정의

라즈베리파이의 LAN 포트로 주변 네트워크 트래픽을 수집·분석하여, 네트워크 안에서 돌아다니는 악성코드·바이러스·침해 시도 등 위험 요소를 탐지하고 "무엇이, 어디서, 무슨 일을 하고 있는지"를 사람이 읽을 수 있는 리포트로 제공하는 **가정/소규모 사무실용 네트워크 보안 센서**.

## 2. 배경과 문제

- 가정과 소규모 사무실 네트워크에는 IoT 기기, 카메라, 개발 보드, PC가 섞여 있지만 어떤 기기가 어디와 통신하는지 아무도 보지 않는다.
- 감염된 기기는 보통 조용하다. C2 서버 비컨, 암호화폐 채굴, 내부 스캔, DNS 터널링은 사용자가 체감하지 못한다.
- 상용 IDS/NDR 장비는 비싸고 복잡하다. 저전력 Pi 5 한 대로 "항상 켜져 있는 감시자"를 만들 수 있다면 비용 대비 가치가 크다.

## 3. 목표 (Goals)

| ID | 목표 | 측정 기준 |
|---|---|---|
| G1 | 네트워크를 지나는 패킷을 24시간 수집한다 | 1Gbps 링크에서 패킷 드롭률 5% 이하 (실사용 부하 기준) |
| G2 | 알려진 위협을 시그니처로 탐지한다 | 공개 룰셋(ET Open) 기반 알림 생성, 테스트 샘플 트래픽 재생 시 탐지 |
| G3 | 알려지지 않은 이상 행위를 탐지한다 | 기기별 기준선(baseline) 대비 이상 통신(신규 외부 목적지, 비정상 시간대, 포트 스캔, DNS 이상)을 플래그 |
| G4 | 네트워크 내 기기를 자동으로 식별한다 | MAC/IP/호스트명/제조사/OS 추정이 담긴 자산 목록 자동 유지 |
| G5 | 위험 요소를 사람이 읽을 수 있는 리포트로 설명한다 | 알림마다 "무엇이 / 어떤 기기가 / 어디와 / 왜 위험한지 / 무엇을 해야 하는지" 5요소 포함 |
| G6 | 즉시 알림과 주기 리포트를 제공한다 | 심각도 높음 이상은 1분 이내 푸시, 일간/주간 요약 리포트 자동 생성 |
| G7 | Pi 한 대에서 무인 운영된다 | 재부팅 후 자동 복구, 디스크 자동 순환, 30일 이상 무인 가동 |
| G8 | 수집한 트래픽을 시계열 데이터로 축적하고, 이를 학습 데이터로 삼아 탐지 모델을 지속적으로 개선한다 | 기기별·구간별 시계열 집계가 끊김 없이 보존되고, 학습 데이터셋을 재현 가능하게 추출할 수 있으며, 주기 재학습 후 탐지 성능(탐지율·오탐)이 추적된다 |

## 4. 범위 밖 (Non-Goals)

- 트래픽 **차단**은 하지 않는다. 이 프로젝트는 탐지와 보고(IDS)이지 방어(IPS/방화벽)가 아니다. 차단은 후속 프로젝트.
- TLS 복호화(MITM)는 하지 않는다. 암호화 트래픽은 메타데이터(SNI, JA3/JA4, 인증서, 흐름 패턴)로만 분석한다.
- 엔드포인트 백신이 아니다. 기기 내부 파일을 검사하지 않고 네트워크에 드러나는 행위만 본다.
- 타인의 네트워크를 감시하는 용도는 설계·문서·기본 설정 어디에서도 지원하지 않는다 (8장 참조).
- 무선(WiFi) 모니터 모드 스니핑은 1차 범위에서 제외한다. 유선 LAN 포트가 기준이다.

## 5. 가장 중요한 설계 결정: 트래픽을 어떻게 볼 것인가

현재 Pi의 eth0은 일반 스위치 포트에 연결되어 있다. 이 상태에서 무차별 모드(promiscuous)를 켜도 **스위치는 Pi에게 다른 기기의 유니캐스트 패킷을 보내주지 않는다**. 보이는 것은 브로드캐스트/멀티캐스트(ARP, mDNS, DHCP, SSDP)와 Pi 자신의 트래픽뿐이다. 따라서 "지나다니는 패킷 수집"이라는 목표를 달성하려면 아래 중 하나를 반드시 선택해야 한다.

| 방식 | 구성 | 가시성 | 장점 | 단점 | 권장 |
|---|---|---|---|---|---|
| **A. 미러(SPAN) 포트** | 관리형 스위치에서 업링크 포트를 Pi 포트로 미러링 | 인터넷 방향 전체 + 미러 대상 포트 간 트래픽 | 네트워크에 영향 없음, 장애 시 서비스 무중단, 구성 단순 | 관리형 스위치 필요(저가 모델 3~5만 원대), 기기 간 내부 트래픽은 미러 설정에 따라 일부만 | **1순위** |
| **B. 인라인 브리지** | 공유기 ↔ Pi(eth0 + USB3 기가비트 NIC 브리지) ↔ 스위치 | 통과하는 모든 트래픽 | 추가 스위치 불필요, 향후 IPS 확장 용이 | Pi 장애 시 네트워크 단절(단일 장애점), USB NIC 성능·안정성 변수, 지연 추가 | 2순위 |
| **C. 공유기에서 직접** | OpenWrt 등 공유기에서 패킷을 Pi로 포워딩 | 전체 | 추가 하드웨어 없음 | 공유기 펌웨어 교체 필요, 공유기 CPU 부하 | 환경 의존 |
| **D. ARP 스푸핑** | Pi가 게이트웨이인 척하여 트래픽을 끌어옴 | 전체 | 하드웨어 불필요 | 네트워크 불안정, 공격 기법과 동일, 자체가 IDS에 탐지됨 | **채택 안 함** |
| **E. 수동 모드(현재 상태)** | 추가 구성 없음 | 브로드캐스트 + 능동 스캔 결과만 | 즉시 시작 가능 | 실제 위협 트래픽 거의 못 봄 | 개발 초기 단계 한정 |

**결정:** 1단계(개발)는 E로 시작하되 아키텍처는 A를 전제로 설계한다. 하드웨어 확보 후 A로 전환한다. B는 IPS 확장 시 재검토한다.

## 6. 기능 요구사항

### 6.1 수집 (Capture)
- FR-1 eth0을 무차별 모드로 열어 패킷을 수집한다. AF_PACKET 기반, 커널 BPF 필터 지원.
- FR-2 원시 패킷은 기본 저장하지 않는다. 흐름(flow)·프로토콜 로그·알림 관련 PCAP 스니펫만 보존한다 (디스크 보호).
- FR-3 알림 발생 시 전후 N초의 패킷을 PCAP으로 잘라 증거로 저장한다 (링버퍼).
- FR-4 수집 드롭 카운터를 노출한다 (자기 진단).

### 6.2 자산 발견 (Asset Discovery)
- FR-5 ARP/DHCP/mDNS/SSDP/LLDP 수동 관찰로 기기를 식별한다.
- FR-6 주기적 능동 스캔(ARP 스캔, 선택적으로 포트 스캔)으로 목록을 보완한다. 능동 스캔은 기본 OFF이며 사용자가 명시적으로 켠다.
- FR-7 기기별로 MAC, 제조사(OUI), IP 이력, 호스트명, 추정 OS/기기 유형, 최초/최근 관찰 시각, 열린 포트를 기록한다.
- FR-8 새 기기 출현 시 알림한다.

### 6.3 시그니처 탐지 (Known Threats)
- FR-9 Suricata 엔진과 ET Open 룰셋으로 알려진 악성코드 C2, 익스플로잇, 스캐너, 피싱 도메인 통신을 탐지한다.
- FR-10 룰셋은 매일 자동 갱신한다 (suricata-update).
- FR-11 위협 인텔 피드(abuse.ch URLhaus/Feodo Tracker/SSLBL, Spamhaus DROP 등)를 IP/도메인/JA3 블랙리스트로 통합한다.
- FR-12 사용자 정의 룰을 추가할 수 있다.

### 6.4 행위 기반 탐지 (Unknown Threats)
- FR-13 기기별 통신 기준선을 학습한다 (목적지 집합, 포트, 시간대, 바이트 분포, DNS 질의 패턴). 학습 기간 기본 7일.
- FR-14 아래 이상 행위를 탐지한다:
  - 내부 포트 스캔 / 호스트 스윕 (lateral movement 징후)
  - 주기적 비컨 (일정 간격의 소량 외부 연결, C2 의심)
  - DNS 이상: 고엔트로피 도메인(DGA), 과도한 TXT/NULL 질의, 비정상 길이(터널링), 비인가 DNS 서버 사용
  - 신규 국가/ASN으로의 첫 연결
  - IoT 기기의 프로파일 이탈 (예: 카메라가 SMTP를 보냄)
  - 대량 외부 업로드 (데이터 유출 징후)
  - 암호화폐 채굴 풀 프로토콜(Stratum) 사용
  - 평문 자격증명 전송 (HTTP Basic, FTP, Telnet)
  - 만료/자체서명/불일치 TLS 인증서 접속
- FR-15 이상 점수와 근거를 함께 기록한다 (설명 가능성).

### 6.5 분석과 상관 (Correlation)
- FR-16 같은 기기·같은 목적지의 알림을 하나의 "사건(incident)"으로 묶는다.
- FR-17 알림에 외부 컨텍스트를 붙인다: 역방향 DNS, GeoIP, ASN, 위협 인텔 매칭, 해당 기기의 최근 행위.
- FR-18 심각도를 정보/낮음/중간/높음/치명 5단계로 산정한다. 산정 근거를 남긴다.

### 6.6 리포팅과 알림 (Reporting)
- FR-19 웹 대시보드: 현재 상태, 기기 목록, 알림 목록, 사건 상세, 트래픽 추이.
- FR-20 사건 상세는 "무엇이 / 어떤 기기가 / 어디와 / 왜 위험한지 / 권장 조치" 구조로 작성된다. 기술 용어는 쉬운 설명을 병기한다.
- FR-21 일간/주간 요약 리포트를 Markdown/HTML로 생성하고 보관한다.
- FR-22 즉시 알림 채널: Telegram 봇(1차), 이메일, 웹훅. 심각도별 채널·조용한 시간 설정.
- FR-23 알림 억제/화이트리스트: 오탐으로 판정한 항목은 사용자가 억제할 수 있고 억제 이력이 남는다.

### 6.7 운영 (Operations)
- FR-24 systemd 서비스로 부팅 시 자동 시작, 장애 시 자동 재시작.
- FR-25 디스크 사용량 상한과 자동 순환 (로그, PCAP, DB).
- FR-26 자가 상태 점검: 수집 중단, 드롭 급증, 룰 갱신 실패, 디스크 부족, 온도 과열을 자체 알림.
- FR-27 설정은 단일 YAML 파일. 비밀값은 별도 파일 또는 환경변수.

### 6.8 시계열 저장과 학습 (Time-Series & Learning)
수집한 트래픽을 일회성으로 검사하고 버리는 것이 아니라, **시계열 데이터로 축적하여 분석하고 학습 데이터로 재사용**한다. 6.4의 기준선 학습은 이 데이터 위에서 동작한다.

- FR-28 **시계열 집계 저장.** 흐름(flow)·DNS·TLS 메타데이터를 기기별·목적지별·프로토콜별로 고정 구간(기본 1분, 5분, 1시간) 단위로 집계하여 저장한다. 집계 지표: 연결 수, 바이트 in/out, 패킷 수, 고유 목적지 수, 고유 포트 수, DNS 질의 수·NXDOMAIN 비율·도메인 엔트로피, TLS 핸드셰이크 수·신규 JA3/JA4 수, 알림 수. 원시 흐름은 별도로 보존하되 구간 집계는 더 길게 보존한다 (계층형 보존: 1분 집계 30일, 5분 집계 180일, 1시간 집계 2년).
- FR-29 **시계열 분석.** 집계 데이터에 대해 기기별 추세·주기성·계절성(시간대/요일)·변화점(change point)을 분석하고 대시보드에 표시한다. 대시보드의 트래픽 추이(FR-19)와 주간 리포트(FR-21)는 이 데이터를 사용한다.
- FR-30 **학습 데이터셋 구축.** 시계열 집계와 흐름 메타데이터로부터 기기별 특징 벡터(feature vector)를 주기적으로 생성하여 학습 데이터셋으로 저장한다. 각 샘플은 생성 시각, 기기, 특징 스키마 버전, 생성에 사용한 원본 구간을 기록하여 **재현 가능**해야 한다.
- FR-31 **라벨 축적.** 사용자의 사건 처리 결과(확인됨/오탐/억제, FR-23)와 시그니처 탐지 결과(FR-9)를 해당 구간의 학습 샘플에 라벨로 연결한다. 라벨이 없는 구간은 비지도 학습(정상 기준선)에 사용한다. 시뮬레이션·재생 PCAP으로 만든 구간은 `synthetic` 플래그로 구분한다.
- FR-32 **주기 재학습.** 기준선 모델(FR-13)과 이상 탐지 모델을 설정된 주기(기본 매일 새벽)로 축적된 데이터로 재학습한다. 모델은 버전·학습 구간·데이터 크기·평가 지표와 함께 저장하고, 이전 버전으로 롤백할 수 있다. 재학습은 Pi의 유휴 시간에 낮은 우선순위(nice)로 수행하며 온도·메모리 상한을 지키면 중단한다.
- FR-33 **모델 평가 추적.** 재학습마다 보유 라벨과 합성 시나리오(비컨·스캔·DNS 터널링 재생)로 탐지율과 오탐률을 측정하여 기록한다. 성능이 이전 버전보다 나빠지면 자동 승격하지 않고 알림한다.
- FR-34 **내보내기·가져오기.** 학습 데이터셋과 모델을 파일(Parquet, 모델 아티팩트)로 내보내고, 다른 장비에서 학습한 모델을 가져와 적용할 수 있다. 내보내기는 기본 OFF이며 수동으로만 수행한다 (8장 외부 전송 금지 원칙). 내보낸 데이터에는 페이로드가 포함되지 않으며 IP·MAC은 옵션으로 가명화한다.

## 7. 비기능 요구사항

| 항목 | 요구 |
|---|---|
| 성능 | 1Gbps 링크, 실사용 평균 50~200Mbps 수준에서 드롭률 5% 이하. Suricata 2~3 워커 스레드, Pi 5 4코어 중 1코어는 수집기·대시보드용으로 남김 |
| 메모리 | 전체 사용량 4GB 이하 (헤드리스 기준 가용 7GB) |
| 저장 | NVMe 215GB 가용 중 기본 50GB 상한. 흐름 로그 90일, 알림 1년, PCAP 스니펫 30일. 시계열 집계는 계층형 보존(1분 30일 / 5분 180일 / 1시간 2년), 학습 데이터셋·모델 아티팩트 합계 10GB 상한 |
| 학습 부하 | 재학습은 유휴 시간에 nice 19로 실행, 1회 30분·메모리 1.5GB 이내. 수집·탐지 경로에 지연을 주지 않음. 온도 70°C 초과 시 재학습 중단 |
| 발열 | 지속 부하 시 70°C 이하 유지 (액티브 쿨러 전제). 과열 시 능동 스캔 중단 |
| 가용성 | 무인 30일 이상. 전원 차단 후 자동 복구 |
| 보안 | 대시보드는 Tailscale 네트워크 내부 또는 localhost에서만 접근. 수집 프로세스는 CAP_NET_RAW/CAP_NET_ADMIN만 가진 전용 사용자로 실행. 외부 인터넷 노출 금지 |
| 프라이버시 | 페이로드 본문 저장 안 함. 메타데이터 중심. 보존 기간 설정 가능. 개인 식별 정보 최소화 |
| 유지보수 | 모든 구성 요소는 apt 또는 pip로 설치 가능해야 하고, 재설치 스크립트 하나로 복구 가능 |

## 8. 법적·윤리적 경계

- 이 시스템은 **운영자가 소유하거나 관리 권한을 가진 네트워크**에서만 사용한다. 타인의 네트워크 트래픽 감청은 통신비밀보호법 등 관련 법률 위반이다.
- 공유 네트워크(가족, 사무실)에서는 구성원에게 모니터링 사실을 고지한다. 설정 파일 첫 항목으로 `monitoring_notice_acknowledged: true`를 요구한다.
- 기본값은 가장 보수적으로: 페이로드 미저장, 능동 스캔 OFF, 외부 전송 OFF.
- ARP 스푸핑 등 공격적 기법은 어떤 모드에서도 구현하지 않는다.

## 9. 시스템 아키텍처 (개요)

```
                 ┌─────────────────────────────────────────────────────────┐
  미러 포트/      │  Raspberry Pi 5 (headless)                              │
  브리지 ──eth0──▶│                                                         │
                 │  [수집·엔진 계층]                                        │
                 │   Suricata (IDS, EVE JSON)   Zeek (프로토콜 로그, 선택)   │
                 │   Python 수동 발견기 (ARP/DHCP/mDNS/SSDP)                 │
                 │   능동 스캐너 (arp-scan / nmap, opt-in)                  │
                 │          │ eve.json / zeek logs / events                 │
                 │          ▼                                              │
                 │  [처리 계층 - Python]                                    │
                 │   수집기(ingest) → 정규화 → 보강(GeoIP/ASN/TI/OUI)        │
                 │   → 시계열 집계(1m/5m/1h) → 기준선 학습 & 이상 탐지        │
                 │   → 상관(incident) → 점수화                              │
                 │   [학습 파이프라인 - 주기 배치]                           │
                 │   특징 추출 → 라벨 결합 → 재학습 → 평가 → 모델 승격        │
                 │          │                                              │
                 │          ▼                                              │
                 │  [저장 계층]                                             │
                 │   SQLite(설정/자산/알림/사건/모델 레지스트리)              │
                 │   Parquet + DuckDB (흐름, 시계열 집계, 학습 데이터셋)       │
                 │   모델 아티팩트 디렉터리 (버전별)                          │
                 │   PCAP 스니펫 디렉터리 (링버퍼)                           │
                 │          │                                              │
                 │          ▼                                              │
                 │  [표현 계층]                                             │
                 │   FastAPI 백엔드 ──▶ 웹 대시보드 (SPA)                   │
                 │   리포트 생성기 (일간/주간 Markdown/HTML)                 │
                 │   알림 디스패처 (Telegram / Email / Webhook)              │
                 └─────────────────────────────────────────────────────────┘
                              ▲ Tailscale / LAN 내부에서만 접근
```

**왜 엔진을 직접 만들지 않고 Suricata를 쓰는가.** 시그니처 매칭, 프로토콜 파서, TLS 핑거프린트, 파일 추출은 수십 년 축적된 영역이다. 이 프로젝트의 차별점은 엔진이 아니라 (1) Pi 한 대에 맞춘 통합과 운영 자동화, (2) 축적한 시계열 데이터로 지속 학습하는 기기 기준선 기반 이상 탐지, (3) 일반 사용자가 이해할 수 있는 설명형 리포트다. 엔진은 가져다 쓰고 그 위에 집중한다.

**데이터 흐름의 원칙.** 모든 탐지·리포트·학습은 같은 시계열 집계 저장소를 읽는다. 실시간 경로(수집→탐지→알림)와 배치 경로(집계→특징→학습)는 저장 계층에서만 만나며, 배치 경로가 실시간 경로를 느리게 해서는 안 된다.

## 10. 기술 스택 (제안)

| 계층 | 선택 | 이유 |
|---|---|---|
| IDS 엔진 | Suricata 7 (apt) | ARM64 패키지 제공, 멀티스레드, EVE JSON 출력, ET Open 룰 무료 |
| 프로토콜 로그 | Zeek (2단계, 선택) | conn/dns/ssl/http 로그 품질이 높음. Pi 자원 여유 확인 후 도입 |
| 패킷 처리 | Python 3.13 + scapy / dpkt, 또는 Rust 보조 모듈 | 수동 발견기 수준에는 Python으로 충분. 성능 병목 시 Rust로 교체 |
| 능동 스캔 | arp-scan, nmap | 표준 도구. 결과 XML 파싱 |
| 처리·API | Python, FastAPI, Pydantic, APScheduler | 빠른 개발, 타입 안전, 비동기 |
| 저장 | SQLite (메타데이터), Parquet + DuckDB (흐름 분석) | 서버 DB 없이 단일 장비 운영. DuckDB로 집계 질의 고속 |
| 시계열 저장 | Parquet을 날짜·구간(1m/5m/1h)으로 파티션, DuckDB로 윈도우·롤업 질의 | 별도 시계열 DB(InfluxDB 등) 없이 같은 스택으로 처리. 파일 단위라 보존·순환·내보내기가 단순 |
| 학습 | pandas 또는 polars(특징 추출), scikit-learn(IsolationForest·robust 통계 기준선), river(온라인/증분 학습), statsmodels(계절성·변화점) | ARM64 pip 휠 제공, CPU만으로 동작, 모델이 작아 Pi에서 재학습 가능. 딥러닝 프레임워크는 1차 제외 |
| 모델 관리 | 파일 기반 아티팩트(joblib/ONNX) + SQLite 모델 레지스트리 | MLflow 같은 서버 없이 버전·지표·롤백 관리 |
| 대시보드 | SvelteKit 또는 React + Vite, 차트는 ECharts | 가벼움. Node 24 이미 설치됨 |
| 알림 | python-telegram-bot, smtplib, httpx | 단순 |
| 보강 데이터 | MaxMind GeoLite2 (무료 계정), IEEE OUI, abuse.ch 피드 | 무료, 자동 갱신 가능 |
| 배포 | systemd 유닛 + 설치 스크립트 (bash/Ansible) | Docker는 AF_PACKET 성능과 권한 복잡도 때문에 1차에서 제외 |
| 테스트 | pytest, 공개 악성 PCAP 샘플(malware-traffic-analysis.net) 재생(tcpreplay) | 실제 위협 트래픽으로 탐지 회귀 테스트 |

## 15. 미결 사항 (Open Questions)

1. 관리형 스위치 구매 여부와 모델. (미러 포트 지원, 기가비트, 5~8포트)
2. Telegram 외 알림 채널 우선순위.
3. 흐름 로그 보존 기간과 디스크 상한 최종값.
4. Zeek을 1차에 포함할지. (메모리·CPU 실측 후 결정)
5. 대시보드 프런트엔드 프레임워크 (SvelteKit vs React). 개발자 선호 반영.
6. 가족/사무실 구성원 고지 방식.
7. 특징 스키마 v1의 구체 항목과 집계 구간(1m/5m/1h) 최종값. Pi 저장 용량 실측 후 조정.
8. 학습 모델 선택: 기기별 개별 모델 vs 기기 유형별 공유 모델. 라벨 축적 전까지는 비지도 기준선만 쓸지.
9. 학습 데이터·모델 내보내기 시 가명화 수준과 형식.
